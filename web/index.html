The embedding model is index-bound; changing it requires rebuilding the schema index. With a separate local router enabled, the search-decision model selects whether to search as written, rewrite first, or skip catalog search. If rewriting is needed, the search-query generation model writes the query; these can be different models. A scope check may finish a request before that decision. With the legacy combined planner, the query model also makes the decision and the selected decision model is inactive. If an external router is configured, it supplies the decision instead of the selected local decision model. The latest response may use a verified graph response or extractive fallback instead of the configured answer model. Questions, answers, stage timings, and failures are stored in the local JSONL query log.

    What does FIOverdraft describe?

    Where can I find the first and last name fields for an individual contact?
