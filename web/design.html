How CDM RAG works.

A FastAPI service retrieves source-linked passages from a pinned Microsoft CDM schema catalog, then uses an Ollama-served model to write a cited answer. Some questions can be answered directly from verified catalog or graph information. The browser streams progress and output as each request runs.

Request path

Check the question

The API assigns a query ID, records the request, then checks relevance and scope before retrieval.

Choose a route

The configured router decides whether to search. With the optional evidence-aware backend, it first inspects up to three hybrid-search excerpts without LLM reranking, then a separate query model rewrites only if requested. Other backends make their decision without that preliminary search.

Retrieve evidence

Chroma semantic search and BM25 lexical search find passages across entities, attributes, relationships, manifests, traits, and inheritance. Eligible entity relationship questions can use explicit graph edges.

Rerank when enabled

After the main search, the answer model can reorder candidate passages before evidence is selected. The default depends on the deployment; a direct graph response can skip this step. This differs from the evidence-aware router's preliminary search, which does not use an LLM reranker.

Write and verify

The generator receives the top passages. Citation normalization and source validation run before the answer is returned.

Stream and record

Status events and answer tokens stream to the UI. The final outcome and stage timings are appended to a JSONL log.

Main components

FastAPI · Python

Validates HTTP requests, coordinates retrieval and model calls, streams results, and serves the web pages and OpenAPI schema.

ChromaDB + BM25 · Python

ChromaDB stores local semantic vectors; BM25 ranks matching words. Reciprocal-rank fusion combines the two lists.

Ollama · host runtime

Serves embedding and chat models. On supported hosts it can use Metal on Apple Silicon or CUDA on an NVIDIA GPU.

JSONL · local disk

Query logs and evaluation runs are stored as files. No separate tracking service or SQL database is required.

Data and evaluation

The bundled catalog is built from a pinned Microsoft CDM source snapshot. The retrieval index contains extracted passages about entities, attributes, relationships, manifests, traits, and inheritance. It contains source links, not customer or account records. The catalog is a documented subset of the full Microsoft CDM repository. At startup the app builds or reuses a local Chroma index and an in-memory lexical ranker.

The Evaluations hub links to saved evaluations for answer generation, held-out graph link prediction, query retrieval, and routing decisions. The detailed evaluation APIs still support new answer, retrieval, relationship, and reranking runs, with completed results stored as JSONL files on disk.
