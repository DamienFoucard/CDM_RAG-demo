MCP integration.

Connect an MCP client to CDM RAG’s first-party tools, locally or on the GPU service.

First-party MCP server

Available tools

ask_schema_question accepts a schema question and returns a bounded answer with source pointers. service_status reports a bounded service and catalog summary. Both tools use existing CDM RAG behavior.

The tools do not expose token administration or private runtime settings. Questions are logged like HTTP API requests. Citations identify evidence; check the sources rather than treating them as a correctness guarantee.

Connect to the GPU service

In your MCP client, choose Streamable HTTP and use your service endpoint, for example:

https://cdm-rag.example.com/api/v1/mcp/

Sign in and create an API token for your client. Supply it through your client’s protected credentials as Authorization: Bearer <API token>. The hosted endpoint uses a manually provisioned token; it does not provide OAuth discovery. Do not put a token in a URL or commit it to a repository.

Connect from a local client

With the local service running, a client can use Streamable HTTP at http://127.0.0.1:8124/api/v1/mcp/, or launch the stdio server from the installed project environment:

uv run python -m app.mcp_stdio

The stdio launcher defaults to the local service. For the GPU service, set CDM_RAG_MCP_BASE_URL to your service origin, for example https://cdm-rag.example.com, and supply CDM_RAG_API_TOKEN through the client’s protected environment. A secured local service also requires a token. Remote backend origins must use HTTPS.

For a client that accepts an mcpServers JSON configuration, replace the example checkout path below with your own. Run uv sync first to install the server dependencies.

{
  "mcpServers": {
    "cdm-rag": {
      "command": "/absolute/path/to/CDM_RAG/.venv/bin/python",
      "args": ["-m", "app.mcp_stdio"],
      "env": {
        "PYTHONPATH": "/absolute/path/to/CDM_RAG",
        "CDM_RAG_MCP_BASE_URL": "http://127.0.0.1:8124"
      }
    }
  }
}

A schema query can take several minutes while models load and run; allow up to 600 seconds for the backend. A timed-out request can continue running until the model worker finishes. Invalid input, unavailable services, timeouts and insufficient evidence are reported to the client. If an answer or its evidence exceeds the MCP response limits, the tool withholds it and reports result_limit_exceeded; use the HTTP API to request the complete result.
